# Демонстрация на защите

## Подготовка

В корне проекта выполните `python run.py --demo` и откройте
`http://127.0.0.1:5173`. Для просмотра запросов откройте в браузере инструменты
разработчика и вкладку **Network / Сеть**, выберите фильтр Fetch/XHR.

## Сценарий на 3–5 минут

1. **Список — GET /api/recipes.** Покажите карточки и фильтры.
2. **Просмотр — GET /api/recipes/{id}.** Нажмите «Открыть»: покажите все поля
   и полный текст ингредиентов и приготовления.
3. **Создание — POST, код 201.** Добавьте рецепт:
   «Омлет», ингредиенты «Яйца — 2 шт.; молоко — 50 мл», шаги «Взбить и обжарить»,
   10 минут, 1 порция, категория «Завтраки». После сохранения список обновится.
4. **Полная замена — PUT, код 200.** Нажмите «Изменить», покажите заполненную
   форму, измените время на 15 минут и сохраните.
5. **Частичная замена — PATCH, код 200.** Нажмите звёздочку. Во вкладке сети
   покажите тело `{"is_favorite": true}` и убедитесь, что другие поля сохранились.
6. **Сохранность.** Остановите сервер через Ctrl+C, снова запустите
   `python run.py`, обновите страницу. Созданный и изменённый рецепт останется в базе.
7. **Удаление — DELETE, код 204.** Нажмите «Удалить», сначала отмените действие,
   затем подтвердите. Карточка исчезнет без перезагрузки страницы.
8. **Ошибки.** Отправьте некорректные запросы из `docs/api.http`: пустое название,
   отсутствующий ID и сломанный JSON. Покажите коды 400/404 и формат `error`/`details`.
9. **Структура.** Покажите SQL-миграцию, валидатор, репозиторий и файл SQLite.
10. **Тесты.** Запустите `python -m unittest discover -s tests -v`.

## Пустой список

Не удаляя основную базу, создайте отдельную тестовую:
в `.env` задайте `DATABASE_PATH=backend/data/empty-demo.db`, затем запустите
`python run.py` **без** `--demo`. Интерфейс покажет пустое состояние с кнопкой
добавления первого рецепта. После демонстрации верните прежний путь базы.

## Что объяснить

- Клиент отправляет HTTP/JSON через `fetch`, API выполняет SQL-запросы.
- SQLite — файловая реляционная база, а не JSON-файл с данными.
- Миграции создают схему автоматически, версии миграций учитываются отдельно.
- PUT заменяет все поля, PATCH изменяет только переданные.
- Серверная валидация работает независимо от проверки HTML-формы.
- `AUTOINCREMENT` не позволяет переиспользовать удалённый ID.
- CORS разрешает запросы клиента с другого порта.
