# По вкусу — веб-приложение «Книга рецептов»

Лабораторная работа: REST API и веб-клиент с полным CRUD для сущности `Recipe`.

**Стек:** Python 3.10+, стандартные модули `http.server` и `sqlite3`, SQLite,
HTML, CSS и JavaScript с `fetch`. Внешних зависимостей и этапа сборки нет.
Клиент работает на порту **5173**, API — на **8000**. Записи хранятся в файловой
базе SQLite и сохраняются после остановки приложения.

## Быстрый запуск

1. Установите Python 3.10 или новее и распакуйте архив.
2. Откройте терминал в папке `recipes-lab`.
3. Запустите:

   ```bash
   python run.py --demo
   ```

4. Откройте [http://127.0.0.1:5173](http://127.0.0.1:5173).
5. Остановите приложение сочетанием **Ctrl+C**.

На Linux/macOS команда может называться `python3`; используйте её вместо `python`
во всех примерах. На Windows можно использовать `py -3`.

`--demo` добавляет шесть демонстрационных рецептов, **только если база пуста**.
Существующие записи не заменяются. Для запуска с пустой новой базой:

```bash
python run.py
```

При обычном запуске приложение не добавляет примеры автоматически. Повторный
запуск открывает ту же базу. Путь по умолчанию — `backend/data/recipes.db`.

## Зависимости и настройка базы

Все зависимости входят в стандартную поставку Python, включая SQLite. Установка
Flask, Node.js, npm или отдельного сервера СУБД для запуска не требуется.
`requirements.txt` фиксирует отсутствие внешних Python-пакетов; при необходимости
можно выполнить привычную команду, она не устанавливает дополнительные пакеты:

```bash
python -m pip install -r requirements.txt
```

Таблицы создаются **SQL-миграцией**, без ручных действий в клиенте СУБД.
Сервер автоматически применяет новые миграции из `backend/migrations/`.
Применённые версии записываются в таблицу `schema_migrations`.
Миграция выполняется в транзакции; повторное применение безопасно.
Для отдельного запуска миграций и заполнения примерами:

```bash
python -m backend.database
python -m backend.seed
```

В базе используется `INTEGER PRIMARY KEY AUTOINCREMENT`: идентификаторы удалённых
записей не выдаются новым рецептам. Данные не хранятся в JSON-файлах или памяти процесса.

## Переменные окружения

Настройки по умолчанию позволяют запускать проект без `.env`. Для изменения
параметров скопируйте `.env.example` в `.env` в корне проекта.
Переменные окружения имеют приоритет над `.env`.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `DATABASE_PATH` | `backend/data/recipes.db` | SQLite-файл; относительный путь считается от корня проекта |
| `API_HOST` | `127.0.0.1` | Адрес привязки REST API |
| `API_PORT` | `8000` | Порт REST API |
| `CLIENT_HOST` | `127.0.0.1` | Адрес привязки клиента |
| `CLIENT_PORT` | `5173` | Порт клиента |
| `API_BASE_URL` | `http://127.0.0.1:8000` | Адрес API, используемый браузером, без `/api/recipes` |
| `CORS_ORIGINS` | `http://127.0.0.1:5173,http://localhost:5173` | Разрешённые источники через запятую |

Если меняете порт клиента, обновите `CORS_ORIGINS`. Если меняете порт API,
обновите `API_BASE_URL`. При `run.py` URL клиента генерируется сервером в `/config.js`
из переменной окружения. Адрес API не зашит в код запросов.

Клиент и API можно запустить двумя отдельными командами в разных терминалах:

```bash
# Терминал 1, корень проекта; читает .env.
python -m backend.server
```

```bash
# Терминал 2, корень проекта.
python frontend/serve.py --port 5173 --api-url http://127.0.0.1:8000
```

При отдельном запуске `frontend/serve.py` настройки читаются из настоящих
переменных окружения либо аргументов командной строки; файл `.env` читает
`run.py` и серверная часть. Открывайте клиент через HTTP, не через `file://`.

## Модель Recipe

| Поле | Тип JSON | Обязательность при POST/PUT | Ограничения |
|---|---|---|---|
| `id` | integer | Генерируется сервером | Положительное целое; нельзя передать в теле запроса |
| `title` | string | Да | 1–200 символов после удаления пробелов по краям |
| `ingredients` | string | Да | 1–4000 символов; поддерживаются переводы строк |
| `instructions` | string | Да | 1–10 000 символов; поддерживаются переводы строк |
| `prep_time` | integer | Да | Время приготовления: 1–1440 минут |
| `servings` | integer | Да | 1–50 порций |
| `category` | string | Нет | До 50 символов; по умолчанию пустая строка |
| `is_favorite` | boolean | Нет | По умолчанию `false` |

Сущность содержит строковые, числовые и логическое поля. `null` не допускается;
для пустой категории используйте `""`. Числовые строки, дроби вместо целых чисел,
числа вместо boolean и неизвестные поля отклоняются. `id` доступен только для чтения.

## REST API

Базовый адрес: `http://127.0.0.1:8000`.
Для POST, PUT и PATCH передавайте `Content-Type: application/json`.
Все ответы с телом имеют формат JSON. GET списка возвращает массив,
при отсутствии записей — `[]`. Список отсортирован по `id` по убыванию.

| Метод | Путь | Действие | Успешный код |
|---|---|---|---|
| GET | `/api/recipes` | Получить все рецепты | 200 |
| GET | `/api/recipes/{id}` | Получить рецепт | 200 |
| POST | `/api/recipes` | Создать рецепт | 201 |
| PUT | `/api/recipes/{id}` | Полностью заменить поля рецепта | 200 |
| PATCH | `/api/recipes/{id}` | Изменить указанные поля | 200 |
| DELETE | `/api/recipes/{id}` | Удалить рецепт | 204, без тела |

POST возвращает созданную запись и заголовок `Location`.
PUT требует все обязательные поля; пропущенные необязательные поля сбрасываются
к значениям по умолчанию. PATCH требует хотя бы одно допустимое поле и сохраняет
остальные. Например, `{"is_favorite": true}` меняет только признак избранного.
Повторный DELETE уже удалённого рецепта возвращает 404.

Пример ответа:

```json
{
  "id": 1,
  "title": "Овощной суп",
  "ingredients": "Морковь — 1 шт.\nВода — 1 л",
  "instructions": "Нарежьте овощи и варите 20 минут.",
  "prep_time": 25,
  "servings": 2,
  "category": "Супы",
  "is_favorite": false
}
```

| Код ошибки | Причина |
|---|---|
| 400 | Ошибка валидации, некорректный JSON/UTF-8, пустое или слишком большое тело, неверный Content-Type или id |
| 404 | Рецепт или маршрут не найден |
| 405 | Метод не поддерживается для выбранного пути |
| 500 | Внутренняя ошибка; подробности пишутся в серверный журнал |

Единый формат ошибки:

```json
{
  "error": "Validation failed",
  "details": ["Поле title обязательно для заполнения"]
}
```

Сервер ограничивает тело запроса 128 КиБ, отклоняет некорректный JSON,
повторяющиеся JSON-ключи и нестандартные значения `NaN`/`Infinity`. Ошибки
запроса не останавливают сервер. CORS включает предварительные запросы OPTIONS
и заголовки на обычных и ошибочных ответах для разрешённых источников.

## Веб-интерфейс

- Карточки рецептов с названием, категорией, временем, числом порций и избранным.
- Ингредиенты и шаги показаны в карточках с сокращением; кнопка **«Открыть»**
  загружает отдельный рецепт по GET и показывает все поля полностью, включая ID.
- **«Добавить рецепт»** открывает форму и отправляет POST.
- **«Изменить»** загружает актуальные значения через GET, предзаполняет форму
  и отправляет PUT.
- **Звёздочка** отправляет PATCH только для `is_favorite`.
- **«Удалить»** открывает диалог подтверждения, затем отправляет DELETE.
- После изменений список автоматически загружается заново без перезагрузки страницы.
- Ошибки сервера отображаются на русском, в форме или возле списка.
- Запросы сопровождаются индикатором загрузки; повторное действие блокируется до завершения.
- Есть пустое состояние, поиск и фильтры по категории и избранному.
- Интерфейс адаптируется к узкому экрану; поля подписаны, диалоги поддерживают клавиатуру.

Рецепты вставляются в DOM через `textContent`: HTML, введённый пользователем,
отображается как текст. Все операции с сущностью выполняются асинхронным `fetch`
через HTTP/JSON, без отправки HTML-форм и перезагрузки страницы.

## Проверка

Интеграционные тесты используют настоящий HTTP-сервер и временный файловый
SQLite; рабочую базу они не изменяют:

```bash
python -m unittest discover -s tests -v
```

Проверяются все шесть эндпоинтов, коды ответов, полная и частичная замена,
валидация, CORS, ошибки JSON, ошибка базы, сохранение после перезапуска,
неповторяемость ID и миграции. Также проверяется выдача файлов клиента и `/config.js`.

Дополнительные тесты транспорта клиента требуют Node.js 18+ **только для проверки**:

```bash
node --test tests/client.test.mjs
```

Результаты выполнения и границы проверки записаны в `docs/VERIFICATION.md`.
Сценарий демонстрации на защите находится в `docs/DEMO.md`;
готовые HTTP-запросы — в `docs/api.http`.

## Если не запускается

- **Порт занят:** остановите предыдущий экземпляр или измените порты и связанные
  URL/CORS в `.env`.
- **Ошибка соединения в браузере:** проверьте запуск API и `API_BASE_URL`.
- **Ошибка CORS:** источник страницы, включая порт, должен присутствовать в
  `CORS_ORIGINS`; после изменения `.env` перезапустите сервер.
- **Не сохраняется база:** путь `DATABASE_PATH` должен указывать в доступный для
  записи каталог. Не удаляйте базу между запусками.
